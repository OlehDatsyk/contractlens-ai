# Security

ContractLens AI processes confidential contracts. This document describes the controls that are implemented, their
limits, and how to report a vulnerability. It does not claim the application is free of vulnerabilities or compliant
with any particular regulation.

## Reporting a vulnerability

Please do not open a public issue. Use GitHub's **private vulnerability reporting** on this repository
(Security → Report a vulnerability). Include steps to reproduce and the affected version. Never include real
contracts or personal data in a report.

## Implemented controls

**Authentication**
- Argon2id password hashing (automatic rehash on parameter changes), password policy, constant-time handling of unknown accounts.
- Short-lived JWT access tokens (HS256 by default, explicit algorithm allow-list, audience/issuer/expiry required) kept in memory by the SPA.
- Refresh tokens are random, stored only as keyed hashes, rotated on every use, revoked on logout/password change, and a reused token revokes its whole family.
- Refresh cookie: `HttpOnly`, `SameSite=Strict`, `Secure` in production, path-scoped to `/api/auth`. Cookie endpoints also require an `X-Requested-With` header (CSRF defence).
- Login rate limiting per IP and per account, temporary lockout after repeated failures, generic error messages; password reset tokens are single-use and expire (30 min default); reset requests do not reveal whether an account exists.

**Authorisation and isolation**
- Every workspace route resolves the caller's membership first; every resource query filters by both resource id and workspace id. Non-members get 404 (no existence leaks). Conversations are additionally private per user.
- Role checks (Owner, Administrator, Analyst, Viewer) are enforced on the server; administrators cannot grant or modify administrator/owner roles; the last owner cannot leave or be demoted.
- Invitations require both a one-time token and a matching account email.
- Automated tests attempt cross-workspace access to contracts, analyses, findings, clauses, obligations, conversations, reports, deadlines, comparisons and downloads via direct API calls.

**Documents**
- Extension allow-list (PDF, DOCX, TXT), declared MIME check, file-signature check, size limit, PDF page limit, text-size limit.
- DOCX: ZIP-bomb limits (entry count, total expanded size, compression ratio), path checks, rejection of macro-enabled documents; embedded objects are ignored. PDF: password-protected files rejected; JavaScript/launch actions are flagged and never executed.
- Parsing runs in a separate process with a hard timeout; failures leave no partial analysis (results are written atomically).
- Files are stored under random server-generated keys (never user filenames), in private storage. Downloads use HMAC-signed links valid for 2 minutes that are bound to user and workspace and re-check membership; responses are `no-store`, `nosniff`, sandboxed by CSP and served as attachments unless the user explicitly views a PDF/TXT.
- Deletion removes database rows and stored files (failed file deletions are retried by the worker). Local-disk deletion overwrites before unlinking (best effort — SSDs and copy-on-write storage may retain data; use encrypted volumes). Configurable per-workspace retention deletes old contracts automatically.

**AI**
- Document text is wrapped as untrusted data, delimiter look-alikes are neutralised, and the system prompt forbids following embedded instructions. Text that looks like instructions to an AI is flagged as a finding.
- Outputs must match Pydantic schemas; quotes are verified against the document; dates must appear in the quoted text; unverified AI findings are labelled and excluded from the score; assistant answers without verifiable citations are withheld.
- Retrieval is scoped to one contract in the caller's workspace. Input size, output tokens and timeouts are capped. API keys are never logged; workspace keys are encrypted at rest (Fernet) and never returned to the browser.

**Web**
- Strict Content-Security-Policy (no inline scripts), `X-Frame-Options: DENY`, `nosniff`, Referrer-Policy, Permissions-Policy, COOP, HSTS in production. React escapes all document text; raw HTML rendering is banned by lint rule.
- CORS limited to configured origins (production serves the SPA from the same origin). Request-body size limits. Validation errors never echo submitted values. CSV exports neutralise spreadsheet formulas.
- SQL is generated by SQLAlchemy with bound parameters; search input is used only as a bound `ILIKE` pattern with wildcards stripped.
- Audit log of security-relevant actions (never document contents); application logs exclude request bodies and document text.

## Known limitations

- Rate limiting is in-process (per instance). Use an edge/WAF limiter for multi-instance deployments.
- No antivirus scanning of uploads (files are never executed, but consider ClamAV if documents are re-shared).
- No multi-factor authentication or email-address verification at registration (invitations mitigate account-email spoofing by requiring the invite token).
- Password reset requires SMTP in production.
- Free hosting tiers are unsuitable for confidential production data (database expiry, no backups).
- AI providers receive contract text when AI is enabled; review provider retention policies.

## Dependency hygiene

CI runs `pip-audit`, `npm audit --omit=dev`, `bandit`, `ruff`, `mypy`, ESLint and type checks on every push.
